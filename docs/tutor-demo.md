# Demo de US04 desde un checkout limpio

Ejecuta los comandos desde la raíz del repositorio y usa una base desechable.
Para un entorno existente, conserva su esquema y sus cuentas. El esquema
mínimo de esta guía sirve para la demo del Tutor.

## Dependencias

- PHP web y CLI 8.1 o superior con `pdo_pgsql`, PDO, `curl`, `mbstring`,
  `zlib`, `session` y `json`. Para subir el PDF mediante Materiales,
  habilita `fileinfo` y configura `upload_max_filesize` y `post_max_size`
  de modo que permitan una subida de 10 MiB más el encabezado del formulario.
- PostgreSQL 16, cliente `psql` y pgvector instalado en el servidor.
- Poppler con `pdftotext` en el PATH del proceso o `TUTOR_PDFTOTEXT_BIN`
  apuntando al ejecutable. La ingesta necesita `proc_open` y temporales
  escribibles. `TUTOR_PDFTOTEXT_CONTAINER` es una alternativa opcional.
- Ollama accesible por loopback desde PHP y los modelos de abajo.
  El índice léxico ya viene incluido. Python solo se usa para regenerarlo.

## Base de datos

Crea una base desechable con el administrador de PostgreSQL. Configura
`PGHOST`, `PGPORT`, `PGDATABASE` y `PGUSER` de `psql` para esa base.
Usa su mecanismo de autenticación habitual. Comprueba el destino con
`psql -X -c 'SELECT current_database()'` antes de aplicar SQL.

Si partes de una base vacía, ejecuta este esquema mínimo en ella.
Si la base de AulaViva ya tiene estas tablas, omite este bloque.

```sql
BEGIN;
CREATE TABLE usuarios (
    id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    colegio_id integer NOT NULL,
    rut text NOT NULL UNIQUE,
    username text NOT NULL UNIQUE,
    nombre text NOT NULL,
    apellido text NOT NULL,
    password_hash text NOT NULL,
    rol text NOT NULL CHECK (rol IN ('profesor', 'alumno', 'admin')),
    activo boolean NOT NULL DEFAULT true
);
CREATE TABLE aulas (
    id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    colegio_id integer NOT NULL,
    nombre text NOT NULL,
    activo boolean NOT NULL DEFAULT true
);
CREATE TABLE aula_profesores (
    aula_id integer NOT NULL REFERENCES aulas(id),
    profesor_id integer NOT NULL REFERENCES usuarios(id),
    PRIMARY KEY (aula_id, profesor_id)
);
CREATE TABLE aula_alumnos (
    aula_id integer NOT NULL REFERENCES aulas(id),
    alumno_id integer NOT NULL REFERENCES usuarios(id),
    PRIMARY KEY (aula_id, alumno_id)
);
COMMIT;
```

Habilita pgvector y aplica las migraciones pendientes, una vez cada una.
Aplica la extensión con una cuenta autorizada para hacerlo.

```sh
psql -X -v ON_ERROR_STOP=1 -c 'CREATE EXTENSION IF NOT EXISTS vector'
psql -X -v ON_ERROR_STOP=1 -f migrations/001_materiales.sql
psql -X -v ON_ERROR_STOP=1 -f migrations/002_evaluaciones.sql
psql -X -v ON_ERROR_STOP=1 -f migrations/003_rendicion.sql
psql -X -v ON_ERROR_STOP=1 -f migrations/004_tutor_rag.sql
```

La 002 y 003 habilitan los módulos enlazados desde el panel general. La
004 requiere la 001 y crea vectores de 768 componentes. Una instalación
preexistente con un esquema experimental distinto requiere una base separada.

Para la demo, prepara un docente y dos alumnos activos en el mismo colegio.
Asigna al docente el aula A, al primer alumno el aula A y al segundo el aula B.
Si aprovisionaste la base vacía, puedes usar el siguiente SQL en ella. Antes,
define `HASH_DOCENTE`, `HASH_ALUMNO_A` y `HASH_ALUMNO_B` en el entorno de
`psql`. Cada valor debe ser el resultado de `password_hash` en PHP sobre
una contraseña elegida para la demo. En Bash puedes generar cada hash
sin mostrar la contraseña ni escribirla en un archivo:

```bash
read -rsp 'Contraseña temporal del docente: ' clave
printf '\n'
export HASH_DOCENTE="$(printf '%s' "$clave" | php -r 'echo password_hash(stream_get_contents(STDIN), PASSWORD_DEFAULT);')"
unset clave
```

Repite el procedimiento con las otras dos variables y ejecuta:

```sql
\getenv hash_docente HASH_DOCENTE
\getenv hash_a HASH_ALUMNO_A
\getenv hash_b HASH_ALUMNO_B
BEGIN;
INSERT INTO aulas (id, colegio_id, nombre) VALUES (1, 1, 'Aula A'), (2, 1, 'Aula B');
INSERT INTO usuarios (id, colegio_id, rut, username, nombre, apellido, password_hash, rol)
VALUES (1, 1, 'demo-1', 'tutor_docente', 'Docente', 'Demo', :'hash_docente', 'profesor'),
       (2, 1, 'demo-2', 'tutor_alumno_a', 'Alumno A', 'Demo', :'hash_a', 'alumno'),
       (3, 1, 'demo-3', 'tutor_alumno_b', 'Alumno B', 'Demo', :'hash_b', 'alumno');
INSERT INTO aula_profesores VALUES (1, 1);
INSERT INTO aula_alumnos VALUES (1, 2), (2, 3);
SELECT setval(pg_get_serial_sequence('aulas', 'id'), (SELECT max(id) FROM aulas));
SELECT setval(pg_get_serial_sequence('usuarios', 'id'), (SELECT max(id) FROM usuarios));
COMMIT;
```

Después puedes limpiar el entorno con `unset HASH_DOCENTE HASH_ALUMNO_A HASH_ALUMNO_B`.

## Aprovisionar la conexión

El checkout integrado ya incluye `config/conexion.php`. Inyecta
`DB_DSN` (DSN PDO con prefijo `pgsql:`), `DB_USER` y `DB_PASSWORD` en
el entorno del CLI y del servidor web. Conserva los valores fuera del
repositorio. En PHP-FPM, asegúrate de que las variables se inyecten también
en sus workers.

## Ollama e ingesta

Inicia `ollama serve` si Ollama todavía no está activo. En el entorno de
PHP y del CLI configura:

```sh
ollama pull nomic-embed-text
ollama pull qwen3:1.7b
export OLLAMA_BASE_URL=http://127.0.0.1:11434
export OLLAMA_EMBEDDING_MODEL=nomic-embed-text
export OLLAMA_CHAT_MODEL=qwen3:1.7b
export TUTOR_AI_TIMEOUT_SECONDS=15
export TUTOR_MAX_CONTEXT_FRAGMENTS=3
export TUTOR_MAX_ANSWER_CHARS=1000
```

## Requisitos de hosting

El servidor necesita PHP con las extensiones anteriores, PostgreSQL con
pgvector y Poppler para la ingesta. PHP debe poder acceder a los proveedores
de generación y embeddings. El CLI también debe acceder al de embeddings.

La demo local usa Ollama. Si el despliegue conserva los adaptadores actuales,
configura `OLLAMA_BASE_URL` con una dirección de loopback accesible desde PHP.
Eso exige que Ollama comparta el espacio de red de PHP y mantenga su puerto
privado. La URL y los modelos se configuran por entorno.

Para usar otro proveedor, implementa `AIProvider` o `EmbeddingProvider` según
corresponda y configura su selección al construir el servicio o el CLI. El
endpoint y el CLI actuales instancian Ollama. Cambiar de proveedor requiere
ese ajuste de integración. Si cambia el modelo de embeddings, reingesta el
corpus para mantener sus vectores y las preguntas en el mismo espacio vectorial
de 768 dimensiones.

Comprueba estas capacidades antes de elegir alojamiento. La imagen Apache
incluye `pdo_pgsql` y Poppler. Conéctala a PostgreSQL externo con pgvector
mediante `DB_DSN`, `DB_USER` y `DB_PASSWORD`. Ollama, si se usa, se ejecuta
fuera de la imagen. La imagen aplica las restricciones HTTP de Apache. Si
usas otro servidor web, configura las restricciones equivalentes.

## Servir desde la raíz

Para la demo local, inicia desde la raíz:

```sh
php -S 127.0.0.1:8000 -t . cli/tutor_demo_router.php
```

El checkout integrado redirige al login de la raíz cuando falta sesión.
El router también resuelve el enlace antiguo `/Aula%20viva/login.php` y
excluye del acceso HTTP los directorios internos del checkout.

Para hosting, usa su servidor web y configura las restricciones fuera del repositorio. La redirección
del ejemplo conserva la compatibilidad con enlaces antiguos. Por ejemplo, agrega al bloque
`server` de nginx, antes de la regla genérica de PHP:

```nginx
location = "/Aula viva/login.php" { return 302 /login.php; }
location ~* ^/(?:cli|config|database|docs|migrations|node_modules|packages|test)(?:/|$) { return 404; }
location ~ (^|/)\. { return 404; }
```

Verifica que `GET /test/tutor-evidence.php` devuelve `404`. La prueba
sigue disponible por consola con `php test/tutor-evidence.php`.

## Verificación de la demo

1. Abre `http://127.0.0.1:8000/tutor.php` sin sesión y comprueba que
   termina en `/login.php`.
2. Entra como docente. En **Mis aulas → Aula A → Materiales**, sube un PDF
   con texto seleccionable. Para tener una pregunta reproducible, puedes
   usar el PDF público [Build Your Own Weather Station](https://cdn.oceanservice.noaa.gov/oceanserviceprod/education/activity-book/pdf/NOAA_DYW_2017_16_Weather_Station.pdf)
   y guardarlo fuera del repositorio. Consulta los IDs con `psql`:
   `SELECT id, aula_id, titulo FROM materiales ORDER BY id DESC;` y
   `SELECT id, username FROM usuarios WHERE rol = 'profesor';`.
3. Ejecuta `php cli/tutor_ingestar.php --material=ID_MATERIAL --profesor=ID_DOCENTE`
   con esos IDs. Comprueba la salida `procesado` con fragmentos.
4. Inicia sesión como alumno A. Abre **Mis cursos → Tutor IA**. Pregunta
   «¿Qué instrumento propone el documento para medir la velocidad del viento?».
   Espera «Anemómetro» con una fuente de la página física 2.
5. Pregunta «¿Qué cantidad de lluvia se registró el primer día con el
   pluviómetro?». Espera el aviso de información insuficiente y ninguna fuente.
6. Abre otra sesión como alumno B. Su aula B carece del PDF. La pregunta
   por el instrumento debe abstenerse. Para comprobar el control en servidor,
   usa la consola del navegador de esa sesión, con el ID del aula A.
   Espera `403` y ninguna cita:

   ```js
   fetch('/tutor_ask.php', {
     method: 'POST',
     headers: {'Content-Type': 'application/json'},
     body: JSON.stringify({aula_id: 1, pregunta: '¿Qué instrumento propone el documento para medir la velocidad del viento?'})
   }).then(async r => console.log(r.status, await r.json()))
   ```

Si el backend agota su plazo, la interfaz debe mostrar exactamente
«El Tutor IA no está disponible en este momento. Inténtalo más tarde».
