# Checklist Tech Lead - S02

## Historias de usuario
- [ ] La historia es clara y entendible.
- [ ] Tiene un objetivo concreto para el usuario.
- [ ] Es técnicamente viable.
- [ ] Es suficientemente pequeña.
- [ ] Se puede verificar mediante pruebas.
- [ ] No tiene dependencias técnicas no identificadas.

## Escenarios
- [ ] Existe un escenario normal.
- [ ] Existe un escenario borde.
- [ ] Existe un escenario de error.
- [ ] Los pasos Given, When y Then son claros.
- [ ] Los escenarios corresponden a la historia de usuario.

## Revisión técnica
- [ ] La solución propuesta es realizable.
- [ ] Las funcionalidades necesarias están identificadas.
- [ ] Se identificaron posibles dependencias.
- [ ] Se identificaron riesgos técnicos.
- [ ] Se consideró la integración entre componentes.

## Control del proyecto
- [ ] El alcance se mantiene dentro del problema definido.
- [ ] Las tareas tienen responsables.
- [ ] Las tareas son realistas para el tiempo disponible.
